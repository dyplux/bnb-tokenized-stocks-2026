# Underlying market state on Sunday

**Observation:** at 2026-10-04 10:48:42 UTC, two signed read-only calls to `GET /api/v1/dex/market/rwa/underlying-market` for BNB Chain NVDA returned `statusInfo.openState=true` and `reasonCode=TRADING`. The Ondo row returned `marketStatus=offhours`; the bStock row returned `marketStatus=null`. The [RWA documentation](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/rwa-data) describes `openState` as whether the *underlying market* is tradable. The [Nasdaq schedule](https://www.nasdaq.com/market-activity/stock-market-holiday-schedule) lists stock-market hours Monday to Friday. [Ondo says](https://ondo.finance/ondo-stocks) NVDAon minting and redemption can run 24/7, which may explain a Sunday open state for that product. The API needs to state which market `openState` represents. This observation doesn't prove the endpoint is wrong.

**Reproduction:** the collector's `python3 scripts/rwa_research.py underlying-probe` makes two permitted signed reads with `binanceChainId=56` and the NVDA bStock/Ondo contract addresses from `data/normalized/rwa_catalog.json`. Sanitized fields and raw-response hashes are in `experiments/EXP-RWA-010/underlying_probe.json`. Complete response fixtures are retained for [bStock](../fixtures/2026-10-04-nvda-bstock-underlying-market-raw.json) and [Ondo](../fixtures/2026-10-04-nvda-ondo-underlying-market-raw.json). No signed request header or secret is stored.

**Additional observation:** the Ondo row reports `nextCloseTime=2026-10-04 23:55 UTC` and `nextOpenTime=2026-10-05 00:05 UTC`, while `openState=true` at 10:48 UTC. Those schedule values may describe a token venue. The API docs should identify which venue and timezone define each state and next-open/close field.

**Repeated live capture:** the detached collector sampled both contracts again at 14:00:02 to 14:00:03 UTC through the same signed endpoint. The bStock response again returned `openState=true`, `reasonCode=TRADING`, `marketStatus=null` and no `marketData.referencePrice` value; raw SHA-256 `63fa400a90e0a8f740796d2e486bb1e91bce415c264c8f1c368a4658048e4ec9`. The Ondo response again returned `openState=true`, `reasonCode=TRADING`, `marketStatus=offhours`, `nextCloseTime=23:55 UTC`, `nextOpenTime=00:05 UTC` and `marketData.referencePrice=234.402941`; raw SHA-256 `a48327fe10b86295dbd1c39c9f1d661daa971d79b7593ba0931b5f030704e304`. The append-only normalized rows are in `data/market_hours/underlying_market_watch.jsonl`; their raw bodies are retained under `data/market_hours/raw/` by hash. This scheduled observation removes the possibility that the first state was a single transient response. It still doesn't identify the market represented by `openState`.

**Reference clock:** both responses include `marketData.referencePrice`, but no timestamp within `marketData`. The top-level `timestamp` is server response time. It can't establish the age of an independent stock reference, and the docs define `referencePrice` as derived from token price.

**16:00 UTC scheduled capture:** the same two-contract watch again returned `openState=true` for both representations. NVDAB had `marketStatus=null` and NVDAon had `marketStatus=offhours`. The exact [NVDAB response](../fixtures/2026-10-04-1600-nvdab-underlying-market-raw.json) has SHA-256 `c4e690c8096f8cb9866a4713c20f1ac4fea32d71746d631410acd158b35e5965`; the exact [NVDAon response](../fixtures/2026-10-04-1600-nvdaon-underlying-market-raw.json) has SHA-256 `a65a94d2ff6a5ea7486909139f896f7d84f1d4e0303c0b12c25b8925afbcba5c`. A recursive field-name scan found only next-open/close times, `marketData.referencePrice` and the top-level response timestamp among time or reference candidates. None dates the underlying stock price. The market represented by `openState` and the next-open/close fields remains unverified; no documentation defect is asserted from this observation alone.
