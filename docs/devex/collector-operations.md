# Live RWA collector operations

The collector runs every 300 seconds while the Mac is awake. Each cycle makes one signed BNB Chain RWA catalog call and one batched price call for 40 stock contracts. The [price endpoint](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/rwa-data) documents up to 100 addresses per request, though a 100-address GET returned HTTP 414 in our probe. The 40-contract universe contains 35 bStock equities and five Ondo equities (AAPL, NVDA, TSLA, COIN, MSTR). A one-off signed probe returned rows for all 130 listed xStocks, but 77 lacked price and timestamp and 36 of the remaining 53 token prices were older than seven days. They remain outside the five-minute tape pending a useful, targeted subset.

```sh
python3 scripts/rwa_research.py start --interval 300 --keep-awake
python3 scripts/rwa_research.py health
python3 scripts/audit_market_tape.py 2026-10-04
```

`start` detaches the loop from its terminal. An exclusive lock prevents a second loop. `health` prints `last_success_at`, `last_attempt_at`, `consecutive_failures`, `observation_count`, `contracts_sampled` and `next_expected_run`; it exits nonzero if the process is missing, more than 60 seconds overdue, retrying after a failure, or stuck in `collecting` for over 90 seconds. The process PID is in `data/market_hours/collector.pid`; its stdout and stderr are in `data/market_hours/collector.log`.

At 15:10 UTC on 4 October, a cycle that started just before a five-minute boundary finished after it. The old loop scheduled sleep from the finish time and left its heartbeat due at 15:10 while sleeping until 15:15. `health` caught the overdue state despite a live PID. The loop now schedules from the slot captured at cycle start and retries promptly when that slot's next boundary has already passed. After restart at 15:13, it captured the 15:10 slot with the actual 15:13 observation time; the 15:15 slot completed on schedule. The 15:15 tape audit found 56 complete slots and no gap record. A synthetic boundary regression is in `tests/test_exact_wallet_simulation.py`.

On this AC-powered Mac, `--keep-awake` launches `caffeinate -s -w <collector-pid>` in a second detached session. It prevents idle system sleep while the collector exists and exits when that PID exits. The 4 October live process was given this assertion at 11:26 UTC; `pmset -g assertions` confirmed `PreventSystemSleep=1`. This doesn't restart a crashed process or survive a reboot; the health command still determines whether collection is active.

Raw API response bodies are stored as gzip files named by SHA-256 in `data/market_hours/raw/`. `raw/manifest.jsonl` is append-only and records every captured response. No request headers or signatures are retained. Sanitized call-level DevEx records go to `docs/devex/raw/YYYY-MM-DD.jsonl`. Normalized `LIVE` observations go to `data/market_hours/YYYY-MM-DD.jsonl` and, within the event window, `data/weekend_2026-10-03_05/`. Each cycle refreshes ignored `data/market_hours/catalog_latest.json`; versioned `data/normalized/rwa_catalog.json` changes only after an explicit `catalog` command. The checkpoint and heartbeat use atomic replacement. Sample IDs combine time slot and contract, so restarting within a slot doesn't duplicate normalized observations. `gaps.jsonl` and `errors.jsonl` record missed slots and failures. Rate-limit responses (HTTP 429 or business code 42900) receive at least 15 minutes of backoff; other consecutive failures use exponential backoff up to one hour. The API's `Retry-After` seconds can lengthen the delay.

No `BACKFILLED` observations have been created. Any future backfill must identify its source, acquisition time and original event time separately. The Saturday 3 October gap remains visible.

The read-only tape audit checks unique LIVE sample IDs, complete slots after the initial partial universe, current token-age arithmetic and gzip bodies against the SHA-256 of their **uncompressed** response. At the 11:45 UTC checkpoint, 596 LIVE rows and 14 complete 40-contract slots passed. Four response hashes in 36 observations from 10:25–10:40 UTC predate raw retention at 10:43 UTC, so their original bodies cannot be verified. The first 45 rows also predate the explicit `reference_age_status=UNKNOWN` field; their reference time and age remain null. The audit counts these historical gaps separately and rejects missing raw hashes or missing reference status in later rows. It never rewrites append-only observations.

**Operational limit, reproduced 4 October at 20:43 UTC:** a one-shot macOS LaunchAgent launched successfully and could `stat` the repository README on this external SSD. The same launch context received `PermissionError: Operation not permitted` when it tried to read the README, collector script and ignored local credential file. The interactive shell could read them. The probe only printed file lengths or error types, never credential values, and was unloaded afterward. This isolates a background file-read permission failure; it does not prove that an unattended collector restart works. No persistent LaunchAgent was installed. The detached collector survives terminal closure, but automatic startup after reboot still requires an OS permission change and a successful end-to-end launch check. After a reboot or SSD remount, run `health`, then `start --interval 300 --keep-awake` only if the recorded collector PID is dead. The next successful cycle records the resulting gap. A Mac sleep period also interrupts collection.
