# Bounded API questions for the Binance Web3 team

**Prepared:** 2026-10-04. These questions are ready for a mentor or official support channel. They have not been sent and no answer is assumed. Each question names a reproducible observation and the product decision it affects.

1. **Market state vocabulary.** `/api/v1/dex/market/rwa/tokens` and `/underlying-market` returned `statusInfo.marketStatus=offhours` for Ondo BSC equities on Sunday. The [RWA Data reference](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/rwa-data) and [official Wallet Skill](https://github.com/binance/binance-skills-hub/blob/main/skills/binance-web3/binance-tokenized-securities-info/SKILL.md) list `premarket`, `regular`, `postmarket`, `overnight`, `closed` and `pause`, not `offhours`. On the same Sunday, `openState=true`, while bStock NVDA market status was null. Which venue and timezone do these fields describe, and should `offhours` be added to the enum? [Request and response repro](repros/2026-10-04-market-status-enum.md). **Decision:** unknown states stay review-required until semantics are clear.
2. **Stock-reference as-of.** Signed `/rwa/price` returns `tokenPriceUpdatedAt` and `referencePrice`; no separate stock-reference timestamp was observed. A public NVDAon Wallet Skill dynamic response returned a distinct `stockInfo.price` but no as-of field. Is there an endpoint with the underlying stock price's source, venue, market-session type and last-update timestamp? If `referencePrice` is token-derived, can the docs say so consistently? [Field repro](repros/2026-10-04-independent-reference-clock.md) and [public Skill repro](repros/2026-10-04-wallet-skill-stock-clock.md). **Decision:** reference age remains `UNKNOWN` until a permitted, independently timed source exists.
3. **RWA route mode.** The [Trading API reference](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/trading-api) says equity/RWA quotes always use `RFQ`, while the [Trading introduction](https://web3.binance.com/en/dev-docs/products/trading-api/introduction) describes bStock `SWAP`. Eight Sunday NVDA/TSLA buy/sell cases across bStock/Ondo returned seven `SWAP` routes and one no-route business code. Which provider, vendor, endpoint, side and market-state combinations should return `RFQ`? Does `SWAP` have different settlement or fee semantics? [Matrix](../../experiments/EXP-RWA-009/route_semantics_matrix.json). **Decision:** the client branches on the observed mode and makes no docs-defect claim yet.
4. **Eligibility check.** A quote and unsigned build for a temporary unfunded wallet succeeded without proving holder or jurisdiction access, and its simulation predicted `FAILED`. The [official bStocks FAQ](https://www.binance.com/en-AU/support/faq/detail/f0c03cd6509a4085b4cce1636f16be38) says a public country-eligibility REST endpoint exists but gives no path or schema on that page; a bounded 4 October search of the public developer references didn't recover it. What are the exact URL, country-code format, response fields and update policy, and is there a separate wallet/asset eligibility check for a self-custody route? How should an integrator handle Ondo restrictions? [Simulation repro](repros/2026-10-04-unsigned-build-simulation.md), [access gate](../research/2026-10-04-issuer-access-gate.md). **Decision:** anonymous checks stay `NEED_HUMAN` and public execution is gated.
5. **Quote lifetime.** A 16:58 UTC exact-wallet NVDAB `SWAP` route had a `quoteId` but no expiry, deadline or valid-until field. What validity period applies to that ID, and which response field or endpoint confirms it for an exact wallet and amount? [Dated response-key observation](repros/2026-10-04-quote-expiry-observation.md). **Decision:** our packet enforces an internal 60-second age limit while treating the provider lifetime as unknown.
6. **Wrapped xStock route coverage.** Two contracts in Binance's public BSC xStock listing, wPOPMTx and wTCENTx, had USDT pairs in a dated DEX indexer response, but signed exact-wallet 10 USDT Web3 `/quote` calls for both returned `40374` and zero routes on 4 October. Are ERC-4626 wrapped xStocks intentionally excluded from this aggregator, or does the response depend on vendor, pair, amount or market state? Is there a supported endpoint that distinguishes “no vendor route” from “no on-chain liquidity”? [Bounded measurement](../research/2026-10-04-xstock-route-fallback.md). **Decision:** an indexed pair never counts as an available route; no xStock fallback is selected.

The Ondo-specific legal question is separate from the Web3 API question. Its [general eligibility page](https://docs.ondo.finance/ondo-stocks/eligibility), [launch announcement](https://ondo.finance/blog/tokenized-stocks-live-on-binance) and [asset-page disclosure](https://app.ondo.finance/assets/vtion) give different EEA access descriptions. For NVDAon, which current final terms, KID, EEA notification and self-custodial venue conditions govern a potential retail holder? This is a request for authoritative issuer documents, not a request to infer eligibility from a route quote. [Access gate](../research/2026-10-04-issuer-access-gate.md).
