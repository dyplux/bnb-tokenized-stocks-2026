# Bounded API questions for the Binance Web3 team

**Prepared:** 2026-10-04. These questions are ready for a mentor or official support channel. They have not been sent and no answer is assumed. Each question names a reproducible observation and the product decision it affects.

1. **Market state vocabulary.** `/api/v1/dex/market/rwa/tokens` and `/underlying-market` returned `statusInfo.marketStatus=offhours` for Ondo BSC equities on Sunday. The [RWA Data reference](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/rwa-data) and [official Wallet Skill](https://github.com/binance/binance-skills-hub/blob/main/skills/binance-web3/binance-tokenized-securities-info/SKILL.md) list `premarket`, `regular`, `postmarket`, `overnight`, `closed` and `pause`, not `offhours`. On the same Sunday, `openState=true`, while bStock NVDA market status was null. Which venue and timezone do these fields describe, and should `offhours` be added to the enum? [Request and response repro](repros/2026-10-04-market-status-enum.md). **Decision:** unknown states stay review-required until semantics are clear.
2. **Stock-reference as-of.** Signed `/rwa/price` returns `tokenPriceUpdatedAt` and `referencePrice`; no separate stock-reference timestamp was observed. A public NVDAon Wallet Skill dynamic response returned a distinct `stockInfo.price` but no as-of field. Is there an endpoint with the underlying stock price's source, venue, market-session type and last-update timestamp? If `referencePrice` is token-derived, can the docs say so consistently? [Field repro](repros/2026-10-04-independent-reference-clock.md) and [public Skill repro](repros/2026-10-04-wallet-skill-stock-clock.md). **Decision:** reference age remains `UNKNOWN` until a permitted, independently timed source exists.
3. **RWA route mode.** The [Trading API reference](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/trading-api) says equity/RWA quotes always use `RFQ`, while the [Trading introduction](https://web3.binance.com/en/dev-docs/products/trading-api/introduction) describes bStock `SWAP`. Eight Sunday NVDA/TSLA buy/sell cases across bStock/Ondo returned seven `SWAP` routes and one no-route business code. Which provider, vendor, endpoint, side and market-state combinations should return `RFQ`? Does `SWAP` have different settlement or fee semantics? [Matrix](../../experiments/EXP-RWA-009/route_semantics_matrix.json). **Decision:** the client branches on the observed mode and makes no docs-defect claim yet.
4. **Eligibility check.** A quote and unsigned build for a temporary unfunded wallet succeeded without proving holder or jurisdiction access, and its simulation predicted `FAILED`. Is there a documented API for a self-custody integrator to verify token-specific user eligibility before showing a signable transaction, including bStock and Ondo restrictions? [Simulation repro](repros/2026-10-04-unsigned-build-simulation.md). **Decision:** anonymous checks stay `NEED_HUMAN` and public execution is gated.
