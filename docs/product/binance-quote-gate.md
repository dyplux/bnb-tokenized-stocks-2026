# Binance Web3 sell quote gate

**Prepared:** 2026-10-01. **Runtime status, 2026-10-02:** the local app's signed identity search and quote path returned one LiquidMesh `SWAP` route for a nonholder technical request; see the [dated observation](../research/2026-10-02-first-live-binance-quote.md). The exact identity check in step 2 runs before the quote. This is a bounded integration gate for the [cash-choice spec](one-page-spec.md), not evidence of an executable holder sale.

## Task and inputs

An eligible NVDAB holder enters a public BNB Chain address, NVDAB units available to sell and a USDT cash target. The current local app can read the ERC-20 balance at one block and display an indexed Venus borrowing scenario. A valid sell comparison needs a fresh, wallet-bound Binance Web3 quote for the **same units**, with any difference from the cash target visible. The address doesn't establish control or jurisdiction eligibility.

## Read-only integration sequence

1. Load the complete `BINANCE_WEB3_API_KEY` and `BINANCE_WEB3_SECRET_KEY` from the ignored private `.env` on the server. Keep both out of browser code, HTTP responses, logs and commits. The [authentication guide](https://web3.binance.com/en/dev-docs/authentication) requires `X-OC-APIKEY`, an ISO timestamp and `X-OC-SIGN` over a path that includes `/build` and the exact query string. It also accepts an `X-OC-NONCE` for replay protection. The local signing helper sends a fresh random nonce per request. The first application-path search and quote authenticated on 2026-10-02; this doesn't verify a future order.
2. Make one signed exact-ticker [RWA search](../research/rwa-probe.md). Accept NVDAB only if the response identifies chain 56, the pinned contract `0x02Fca66C1D1aFB4E2A7884261eB00F63598a7436`, and the bStock platform. Record latency, API business code and a redacted identity result. A malformed response blocks the quote.
3. Convert the entered token units to an integer raw amount using `decimals()` read from the NVDAB contract at a recorded block. The [Trading API quote](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/trading-api) takes `binanceChainId=56`, the pinned NVDAB and USDT contracts, `amount` in the sell token's smallest unit and `userWalletAddress` for RFQ routes. Make one signed `GET /api/v1/dex/aggregator/quote`. No `/swap`, approval, order or broadcast belongs in this gate.
4. Treat HTTP 200 with a non-zero Binance business `code` as an error. Distinguish missing credentials, authentication, region, market hours, unsupported pair, no liquidity, rate limit and malformed route. Record codes and latency without raw signed URLs, headers, quote IDs or wallet addresses. An empty route list means **no observed route**, not a zero-price sale.
   `capture_time_utc` in the local app is when the HTTP response was received. It isn't the underlying stock price timestamp or a promise that an expiring quote remains executable.
5. Official docs conflict: the [Trading API introduction](https://web3.binance.com/en/dev-docs/products/trading-api/introduction) says bStocks can return LiquidMesh `SWAP` and PcsXRfq `RFQ` together, while the [quote response reference](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/trading-api) says equity/RWA routes always use `RFQ`. Preserve each route's observed mode and vendor. Treat an NVDAB `SWAP` route as review-required until a live response and execution path reconcile the discrepancy. A route `quoteId` lasts about 30 seconds. Do not expose it in a dated receipt or promise an executable quote after expiry.
6. Before marking any returned route observed, require `binanceChainId="56"`, exact NVDAB and USDT contract/symbol metadata, documented decimal strings matching on-chain `decimals()` at the same recorded BNB block, `fromTokenAmount` equal to the requested integer input, and a positive integer `toTokenAmount`. The [live response](../research/2026-10-02-first-live-binance-quote.md) confirmed these fields for a temporary address and reported 18 decimals for both tokens. It also showed a LiquidMesh `SWAP`, `tradeFee`, `estimateGasFee` and null custom-fee fields. Preserve amounts as estimated base-unit strings in the app. Fee scope, transaction execution and final received amount remain unresolved. Keep the sale **Unquoted** in the scenario and say **route observed, proceeds unverified** after a route request.

## Release gate

A technical nonholder quote now establishes signed access, one observed route mode, raw amount units and response timing. It doesn't pass the holder task gate. One permitted holder-sized response and the same-task observation must establish whether this changes a real cash choice. The [DX field log](../dx/field-log.md) records actual times, codes and selected fields. A quote is an estimate; it doesn't establish a fill, net settled proceeds, profit or user eligibility.
