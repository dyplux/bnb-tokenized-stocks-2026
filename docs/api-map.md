# Binance API map, observed research stage

**Checked:** 2026-10-04. This table combines official documentation with linked live observations. Signed RWA catalog and price calls, holder ranking, Trading quotes and DeFi Positions reads, plus an unsigned SWAP-build read, have succeeded. No order or transaction has been submitted.

| Surface | Research use | Known constraint | Next observation |
|---|---|---|---|
| Binance website public [RWA list](https://www.binance.com/bapi/defi/v1/public/wallet-direct/buw/wallet/market/token/rwa/stock/detail/list/ai?type=3) | Read-only candidate ticker, BNB Chain contract and multiplier discovery; [2026-10-01 snapshot](research/2026-10-01-binance-public-preopen-probe.md). | Website BAPI is separate from the signed Binance Web3 developer API. Its `openState` and `tokenInfo.price` do not establish a wallet-specific execution route. | Confirm candidate contracts and fields through the signed RWA API and issuer. |
| [Binance Spot public market data](https://developers.binance.com/en/docs/products/spot/rest-api) | CEX order-book control for amount-sensitive bid/ask research. | CEX Spot liquidity is not BNB Chain RFQ liquidity and does not satisfy the event's Web3 API requirement. | Compare only after a same-time, same-size signed Web3 quote exists. |
| [Binance Stocks Trading market data](https://developers.binance.com/en/docs/catalog/advanced-trading-stocks-trading/api/rest-api/market-data) | Potential independent conventional-equity bid/ask and symbol tradability control for an eligible Binance account. | It requires a separate `X-MBX-APIKEY`; the Web3 key and `X-OC-*` headers don't authenticate it. Its quote can be empty and has no documented server timestamp in the example. No account key or live call has been used here. | Seek account eligibility and permitted access before use. Match ticker, unit and time; don't present this API as part of the required Web3 integration. |
| [RWA Data API](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/rwa-data) | Catalog, token price and underlying-market context. The [4 October snapshot](research/2026-10-04-live-rwa-catalog-and-quotes.md) captured 488 signed catalog rows; a separate public listing added 130 xStocks. | A 100-address price GET returned HTTP 414 despite the documented maximum of 100; 35-address batches worked. Of 130 listed xStocks probed, 77 returned null price and time. The five-minute tape deliberately samples 40 contracts, not the full catalog. | Continue the 40-contract tape through a regular US market session, and request only a targeted xStock subset if it changes a user task. |
| [DeFi positions API](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/defi-data) | A [bounded signed read](research/2026-10-03-binance-defi-positions-coverage.md) showed NVDAB `supply` and USDT `borrow` roles under Venus for a selected public account. | The probe didn't retain whether those roles belonged to the same position. The response wasn't reconciled to an exact Core pool, block or amount. Its server timestamp isn't an on-chain block, and current positions don't forecast post-action risk. | Use only as account-position context after same-block Core reconciliation. Do not turn this response into a personal safe-borrow result. |
| [Holder-ranking API](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/general-data) | A [bounded signed read](research/2026-10-03-nvdab-holder-debt-overlap.md) returned 48 vNVDAB holder addresses; fixed-block Venus reads checked the first 15. | Rankings are biased towards large token balances and don't identify people or their cash tasks. The response has no pagination or per-holder block. | Use only to study account-state overlap. A consenting holder task remains necessary for the product decision. |
| `referencePrice` in RWA Data | The [Wallet Skills guide](https://web3.binance.com/en/dev-docs/products/wallet-skills/supported-skills) describes a token-price/share-multiplier calculation. The [4 October freshness audit](../experiments/EXP-RWA-010/results.json) checked signed `/rwa/price` and two `/rwa/underlying-market` payloads. | `tokenPriceUpdatedAt` times the **token price**. Neither checked payload provided an independent underlying-reference timestamp; all 356 observed tape rows through 11:15 UTC have `reference_age_status=UNKNOWN`. The response-level `timestamp` is server time. `referencePrice` cannot establish an independent stock-price discount or freshness. | Ask Binance whether another permitted feed exposes a timed independent TradFi benchmark. Record source rights, unit and market state before using one. |
| [Trading API](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/trading-api) | Request a spot quote for a fixed token, wallet and amount. A [live technical app-path request](research/2026-10-02-first-live-binance-quote.md) returned one LiquidMesh SWAP route for 1 NVDAB to USDT; a later [read-only `/swap` GET](research/2026-10-02-first-live-swap-build.md) built one unsigned transaction payload. | The [introduction](https://web3.binance.com/en/dev-docs/products/trading-api/introduction) allows bStock SWAP and RFQ routes, while the endpoint reference says equity/RWA always uses RFQ. The observed SWAP contradicts that reference. A quote ID lasts about 30 seconds; the temporary nonholder address and unsigned payload don't prove executable or net proceeds. | Confirm vendor fee and approval-gas semantics with Binance, then request a holder-sized quote for a consenting eligible holder's same cash task. No transaction signing or broadcast at this gate. |
| [Transaction API](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/transaction-api) | Signed `POST /api/v1/dex/pre-transaction/simulate` accepts chain `56` and an unsigned EVM `from`, `to`, `value`, `data` transaction; it returns predicted status, balance changes and allowance changes. | The observed NVDAB route was `SWAP`, and `/swap` built an unsigned payload for a temporary nonholder. The docs don't describe a balance or allowance override, so simulating that payload from an unfunded nonholder cannot establish an executable holder sale. No Transaction API call has been made. | After the product checkpoint, map a fresh build to the documented EVM fields for a consenting funded holder, preserve the predicted failure or success and compare with actual receipt only if the founder authorizes a small live transaction. See the [simulation boundary](research/2026-10-03-transaction-simulation-boundary.md). |
| [API authentication](https://web3.binance.com/en/dev-docs/authentication) | Signed server-side calls with account credentials. | A no-wallet-signature demo still needs HMAC API authentication. | Verify least-permission scope and quota privately; never put keys or signed headers in repo or logs. |
| [Agentic Wallet stock flow](https://developers.binance.com/en/docs/products/agentic-wallet/use-cases/trading/stock-trading) | Incumbent baseline and possible optional integration. | Already resolves ticker and documents quote, confirmation and tracking. | Observe same task before adding any agent interface. |
| [bStocks country eligibility](https://www.binance.com/en/support/faq/detail/f0c03cd6509a4085b4cce1636f16be38) | Third-party applications should enforce bStocks geographic restrictions using the issuer's stated public REST endpoint. | A [bounded primary-source search](research/2026-10-03-bstocks-country-endpoint-search.md) on 2026-10-03 found no route or schema. The Web3 API prohibited-region list is a separate access control, not an investor eligibility response. | Obtain the exact issuer endpoint and failure behavior before exposing trade actions; never infer eligibility from wallet or Web3 API access. |
| [BNB Agent Studio](https://docs.bnbchain.org/developer-kit/bnbchain-studio/quickstart/) | Optional paid source-to-quote seller service for other agents, if it materially improves the task. | Current quickstart describes a TypeScript seller with A2A/MCP/x402 and a managed 48-hour testnet trial. No scheduler or mainnet stock-trading wallet path was demonstrated. ERC-8183 fulfillment could outlast the approximately 30-second RFQ quote. | Try a local/testnet job only after the core user task and buyer need are proved; measure end-to-end time. |

The research tape and read-only quotes do not imply execution, backing certification, independent exchange-price comparison or profitability. Record real onboarding, errors, latency and field availability contemporaneously for the mandatory Developer Experience Report.
