# Binance API map, documentary stage

**Checked:** 2026-10-01. The endpoints and field descriptions below come from official documentation. No authenticated request, live response, quote, order or transaction has been observed by this new project.

| Surface | Documented use for H1 | Known constraint | Next observation |
|---|---|---|---|
| Binance website public [RWA list](https://www.binance.com/bapi/defi/v1/public/wallet-direct/buw/wallet/market/token/rwa/stock/detail/list/ai?type=3) | Read-only candidate ticker, BNB Chain contract and multiplier discovery; [2026-10-01 snapshot](research/2026-10-01-binance-public-preopen-probe.md). | Website BAPI is separate from the signed Binance Web3 developer API. Its `openState` and `tokenInfo.price` do not establish a wallet-specific execution route. | Confirm candidate contracts and fields through the signed RWA API and issuer. |
| [Binance Spot public market data](https://developers.binance.com/en/docs/products/spot/rest-api) | CEX order-book control for amount-sensitive bid/ask research. | CEX Spot liquidity is not BNB Chain RFQ liquidity and does not satisfy the event's Web3 API requirement. | Compare only after a same-time, same-size signed Web3 quote exists. |
| [Binance Stocks Trading market data](https://developers.binance.com/en/docs/catalog/advanced-trading-stocks-trading/api/rest-api/market-data) | Potential independent conventional-equity bid/ask and symbol tradability control for an eligible Binance account. | It requires a separate `X-MBX-APIKEY`; the Web3 key and `X-OC-*` headers don't authenticate it. Its quote can be empty and has no documented server timestamp in the example. No account key or live call has been used here. | Seek account eligibility and permitted access before use. Match ticker, unit and time; don't present this API as part of the required Web3 integration. |
| [RWA Data API](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/rwa-data) | Search tokenized stocks, get underlying profile, price and underlying-market context. | Documentation lists `platformId` values `ondo` and `bstock`. Token data, ratios and timestamps need live validation. | Probe one NVDA token per supported platform and record redacted fields and latency. |
| `referencePrice` in RWA Data | Described as an underlying reference price in the RWA endpoints, but the [Wallet Skills guide](https://web3.binance.com/en/dev-docs/llms-full.txt) also gives `referencePrice = tokenPrice / sharesMultiplier`. The official example values don't satisfy that equation. | Provenance and underlying quote timestamp are unspecified; independence is **unconfirmed**. Subtracting it from `tokenPrice` doesn't establish a discount or arbitrage. See the [source audit](research/2026-10-01-reference-price-source-audit.md). | Ask Binance which upstream quote and timestamp populate the field. If an independent TradFi benchmark is needed, verify source rights, unit and time before using it. |
| [Trading API](https://web3.binance.com/en/dev-docs/llms-full.txt) | Request a spot quote for a fixed token, wallet and amount. A [research-only single-request probe](research/quote-probe.md) is prepared. | The [execution-mode guide](https://web3.binance.com/en/dev-docs/llms-full.txt) says Ondo routes use RFQ, xStocks use SWAP, and bStocks can return LiquidMesh SWAP and PcsXRfq RFQ routes together. Branch on each returned `executionMode`. An RFQ signer must match `userWalletAddress`; a quote ID lasts about 30 seconds. Live availability and costs remain unobserved. | Request one authentic holder-sized sell quote without signing or submitting an order once local credentials and raw units are confirmed. Record each route's mode, latency and disclosed costs; expand sizes only if needed. |
| [Transaction API](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/transaction-api) | Possible transaction simulation. | `evmTx` simulation has not been shown to simulate the same RFQ operation. | Check compatibility before claiming any simulation in the product. |
| [API authentication](https://web3.binance.com/en/dev-docs/authentication) | Signed server-side calls with account credentials. | A no-wallet-signature demo still needs HMAC API authentication. | Verify least-permission scope and quota privately; never put keys or signed headers in repo or logs. |
| [Agentic Wallet stock flow](https://developers.binance.com/en/docs/products/agentic-wallet/use-cases/trading/stock-trading) | Incumbent baseline and possible optional integration. | Already resolves ticker and documents quote, confirmation and tracking. | Observe same task before adding any agent interface. |
| [bStocks country eligibility](https://www.binance.com/en-NG/support/faq/detail/f0c03cd6509a4085b4cce1636f16be38) | Third-party applications must check whether a jurisdiction may access bStocks. | Binance FAQ mentions a public REST endpoint, but its route and response schema were not found in the official pages checked. Wallet ownership does not establish eligibility. | Ask the issuer or organizer for the exact endpoint before exposing trade actions. |
| [BNB Agent Studio](https://docs.bnbchain.org/developer-kit/bnbchain-studio/quickstart/) | Optional paid source-to-quote seller service for other agents, if it materially improves the task. | Current quickstart describes a TypeScript seller with A2A/MCP/x402 and a managed 48-hour testnet trial. No scheduler or mainnet stock-trading wallet path was demonstrated. ERC-8183 fulfillment could outlast the approximately 30-second RFQ quote. | Try a local/testnet job only after the core user task and buyer need are proved; measure end-to-end time. |

The initial research test can end at a quote and dated decision receipt. It must not imply execution, backing certification, independent exchange-price comparison or profitability. Record real onboarding, errors, latency and field availability contemporaneously for the mandatory Developer Experience Report.
