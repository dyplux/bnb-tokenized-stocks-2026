PRE-SIGNING SAFETY FOR AUTONOMOUS TOKENIZED-EQUITY AGENTS

A quote can exist while the trade still needs a stop.

Before an agent buys a tokenized equity, Praeva checks the exact contract, market state, share multiplier, route and spending mandate. It records whether issuer access, an independent reference clock and a funded simulation have been verified. The deterministic policy returns ALLOW, DENY or NEED_HUMAN with a hashed receipt.

    WHAT THE JUDGE CAN CHECK

    A narrow claim, with the unknowns intact

    1. Inspect both observed cases. The first replay preserves a captured signed Binance Web3 quote and a fixed-block multiplier check. Its NEED_HUMAN reasons name facts the APIs didn't establish. The second captured a fresh route but returns DENY because 100 USDT exceeds a 20 USDT mandate. The local read-only screen uses a temporary generated address for its quote; these receipts don't establish a particular holder's access. The on-chain audit explains the fixed-block method.
    2. Verify the receipt hash. Download the JSON. Remove `receipt_sha256` from `receipt`, serialize the remaining object with sorted keys and compact separators, then calculate SHA-256. The page checks it in your browser too. This checks the decision body's consistency. The signed API response bodies named by its source hashes are retained locally and aren't served by this page.
    3. Run the live path. Clone the public repository and follow judge instructions. Your own Binance Web3 API credentials are needed for a fresh signed read. The public page doesn't hold an API key.

    In a measured 40-contract sample, referencePrice matched token price divided by the share ratio at reported precision. Its upstream source and underlying-stock as-of time remain unverified. tokenPriceUpdatedAt dates the token price. A displayed quote, an ALLOW fixture and an API simulation response don't prove eligible access or a completed trade.
