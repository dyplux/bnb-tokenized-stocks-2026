# A generic RWA policy gateway has a direct substitute

**Checked:** 2026-10-04 UTC. **Scope:** pinned [OneTicker README](https://github.com/JemIIahh/oneticker/blob/2a4a6f5f28e50f65eb70073a1f9597ea9cd12346/README.md), its [market clock](https://github.com/JemIIahh/oneticker/blob/2a4a6f5f28e50f65eb70073a1f9597ea9cd12346/packages/core/src/market/clock.ts), [gate](https://github.com/JemIIahh/oneticker/blob/2a4a6f5f28e50f65eb70073a1f9597ea9cd12346/packages/core/src/gate/gate.ts), and [APRO client](https://github.com/JemIIahh/oneticker/blob/2a4a6f5f28e50f65eb70073a1f9597ea9cd12346/packages/clients/src/chain/apro.ts). These are code and self-reported product claims, not an independent live walkthrough.

OneTicker already publishes token resolution across bStocks, Ondo and xStocks; per-share normalization; amount-specific quotes; a deterministic GO/CAUTION/BLOCK gate; MCP and Wallet Skill surfaces; and a five-minute off-hours tape. Its README says the tape began 22 September, earlier than our 4 October collector. It also names APRO feeds, pool depth, collateral indices and perpetual prices. Our current 40-contract signed tape is broader than its stated five-ticker tape, but breadth alone isn't a distinct user outcome. A generic routing, quote-guard or MCP wrapper would overlap this project heavily.

The source reveals a narrower semantic question. Its `marketClock()` sets `referenceAgeSec` to seconds since the calendar's previous US regular-session close, and zero during regular hours. That is an elapsed **session-clock** duration, not an observed update timestamp of a specific reference price. Its gate uses that duration when a `referenceSep` is present. This might be a useful risk heuristic, but it doesn't prove the supplied price was refreshed at the previous close. Don't call the code broken on that basis; the referenced price source and full live behavior need separate tracing.

APRO's official [BNB Chain feed list](https://docs.apro.com/en/data-push/price-feed-contract) contains NVDAB/USD. Our own read-only [fixed-block snapshot](../../data/external_reference/2026-10-04-apro-nvdab.json) confirms a real oracle `updatedAt` of 12:31:25 UTC at a 12:35:04 UTC block, age 219 seconds. The feed description is **NVDAB/USD**, so this is a timestamp for a tokenized-equity oracle round. It doesn't fill Binance's missing independent NVDA stock-reference clock.

**Decision effect:** don't build a generic policy gateway and call the gate, MCP surface or off-hours tape original. A provenance-bound clock check remains a research candidate only if it produces a different, useful action for an agent developer or trader and can obtain a genuinely independent source for the claim it makes. The currently measured output is often `UNKNOWN`, and there is no confirmed user demand for another guard.
