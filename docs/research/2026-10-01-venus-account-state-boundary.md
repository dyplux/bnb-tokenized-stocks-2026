# Venus Core account-state boundary

**Checked:** 2026-10-01. **Runtime observation:** none for a holder account. This note sets the next read-only gate; it is not a personal borrowing calculation.

## Why the current screen stops at a scenario

The local app reads a public NVDAB wallet balance and indexed Venus market fields. A wallet's token balance is outside Venus. It doesn't establish supplied collateral, existing debt or E-Mode. The app therefore labels its health factor and price-drop values as isolated assumptions.

Venus identifies NVDAB in the BNB Chain **Core Pool**, whose Comptroller was observed at `0xfD36E2c2a6789Db23113685031d7F16329158384` in the [fixed-block oracle read](2026-10-01-venus-bstock-oracle-check.md). The [Core MarketFacet reference](https://docs-v4.venus.io/technical-reference/reference-core-pool/comptroller/diamond/facets/market-facet) says `getAssetsIn(address)` lists the vToken markets an account has entered. It warns to call selectors through the Unitroller and check the live selector map. The [Core PolicyFacet reference](https://docs-v4.venus.io/technical-reference/reference-core-pool/comptroller/diamond/facets/policy-facet) distinguishes `getBorrowingPower(address)`, based on collateral requirements, from `getAccountLiquidity(address)`, based on liquidation thresholds. These are not interchangeable safety numbers. [Venus's E-Mode guide](https://docs-v4.venus.io/whats-new/e-mode) says effective risk factors depend on the user's selected `userPoolId`.

## Narrow next read

At one recorded BNB block, confirm chain 56 and Core Unitroller code, check that `getAssetsIn(address)` maps to a live facet, and call the inherited `userPoolId(address)` getter directly through the Unitroller. For a public address, read both results at that block. A missing, malformed or reverting result means **account state unknown**. A nonempty entered-market list or nonzero E-Mode pool means **existing Venus configuration detected**; suppress any personal liquidation or borrow-feasibility claim. Even an empty list is only an observed Core membership state at that block. It doesn't prove no positions elsewhere or that a new loan will execute. Do not copy the indexed market APR or pool cash into an account-specific approval.

If a personal loan scenario is eventually needed, read all relevant supply and debt balances and the Core effective factors at the same block, account for bounded oracle behavior and protocol pause/caps, then compare a hypothetical borrow with the Comptroller's own checks. A single NVDAB balance or `getAccountLiquidity` number cannot replace that work. Keep the user at the existing Venus transaction interface for a fresh confirmation; this product remains read-only.

## Decision

Implement a small account-state notice only after the deployed Core read path and response ABI are confirmed. Keep the existing hypothetical values visibly hypothetical for every address. If a complete account read cannot be made safe before submission, the [D-017 stop rule](../decisions/decision-log.md) applies. No address, position or personal jurisdiction data belongs in this document or the committed DX log.

## Simulation boundary checked against current official docs

The [PolicyFacet reference](https://docs-v4.venus.io/technical-reference/reference-core-pool/comptroller/diamond/facets/policy-facet) documents `getBorrowingPower(address)` for collateral requirements, `getAccountLiquidity(address)` for liquidation thresholds, and `getHypotheticalAccountLiquidity(address,address,uint256,uint256)` for a hypothetical redemption or borrow. That hypothetical method has no new-supply argument. A wallet holding NVDAB outside Venus cannot be modeled as if it had already deposited that token by calling this method once. The contract's returned liquidity also does not by itself check every market pause, cap or transaction precondition. A future personal comparison needs an account-wide, same-block model and transaction-policy checks, or it must keep the borrow side explicitly hypothetical. The current UI takes the latter route.
