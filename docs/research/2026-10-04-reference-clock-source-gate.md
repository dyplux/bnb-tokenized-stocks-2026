# What would count as an independent stock clock?

**Checked:** 2026-10-04 UTC. **Decision use:** separate a token price's update time, an issuer reference update, and an external stock trade. These are different observations even when their prices coincide.

| Surface | Timestamp evidence | Can it supply the missing issuer reference clock? |
|---|---|---|
| Signed [Binance Web3 RWA API](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/rwa-data) | `tokenPriceUpdatedAt` dates the token price. `referencePrice` is documented as derived from token price. The observed `/price`, `/underlying-market` and `/underlying-profile` responses supplied no independent reference update time. [Field-level repro](../devex/repros/2026-10-04-independent-reference-clock.md). | **No, in observed fields.** Leave `reference_price_updated_at=null` and `reference_age_status=UNKNOWN`. |
| Public Binance website dynamic BAPI | In retained Sunday [AAPLon and NVDAB responses](../devex/repros/2026-10-04-public-stock-reference-clock.md), AAPLon's `stockInfo.price` equals token price divided by the share multiplier at displayed precision; NVDAB's stock price is null. Neither includes a stock-price timestamp. | **No, in observed fields.** The arithmetic doesn't identify the upstream price source. This BAPI is separate from the signed developer API. |
| [APRO NVDAB/USD on BNB Chain](https://docs.apro.com/en/data-push/price-feed-contract) | A read-only [block-pinned round](../../data/external_reference/2026-10-04-apro-nvdab.json) at block 125677197 reported `updatedAt=2026-10-04 12:31:25 UTC`, 219 seconds before its block, and `description=NVDAB/USD`. APRO's [ABI reference](https://docs.apro.com/en/data-push/evm-guides/price-feed-api-reference) defines `updatedAt` as the round update time. | **Timed tokenized-equity oracle, not the issuer's underlying NVDA stock clock.** It may support a separate token-oracle freshness guard. Don't assign its age to `reference_age_seconds`. |
| [Alpaca Market Data FAQ](https://docs.alpaca.markets/us/docs/market-data-faq) | Its documented latest stock-trade response includes `trade.t`, a trade timestamp, `trade.p`, price, and exchange code. The FAQ says the default free feed is IEX and recent SIP latest data requires a subscription. | **External trade benchmark candidate only.** A trade on one feed isn't the token issuer's declared valuation reference. Access credentials and data rights would need review before integration. No Alpaca call has been made. |
| [Nasdaq Cloud last-trade specification](https://github.com/Nasdaq/NasdaqCloudDataService-REST-API/blob/main/restapi/lasttrade.md) | Documents a trade timestamp for its last-trade product. | **External benchmark candidate only.** Product access and terms haven't been checked. No Nasdaq Cloud authenticated call has been made. |
| Dated [Yahoo Finance history rows](https://finance.yahoo.com/quote/NVDA/history/) | Session-date daily open and close fields, used only for [the frozen Monday comparison](../../experiments/EXP-RWA-004/monday-open-protocol.md). | **No intraday reference clock.** A daily date isn't an update timestamp and isn't the issuer's feed. |

**Gate:** if a future app claims to reject a stale underlying reference, it must name the exact source, timestamp semantics, market session and allowed data use. If only a dated external trade is available, call the result an external benchmark comparison. Don't relabel it as the issuer's own reference freshness.
