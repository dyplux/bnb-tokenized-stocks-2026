# D-017 stop-rule review

**Date:** 2026-10-03 UTC. **Role:** Plus Sol, read-only. **Question:** should the provisional NVDAB sell-or-borrow product be retired at the 4 October checkpoint? The reviewer read the current spec, cap screen, market snapshot, incumbent comparison, decision log and readiness gates. No holder, signed API, code edit or wallet action was used in this review.

## Recommendation and evidence

The reviewer recommends **retiring D-017 at the 4 October checkpoint** unless new evidence changes its release gates. The app has a real signed Binance Web3 quote path and a same-cash display, and the [3 October market snapshot](../../research/2026-10-03-cash-task-market-snapshot.md) makes a 1 NVDAB / 100 USDT isolated scenario arithmetically possible. The [cap screen](../../research/2026-10-02-bstock-collateral-cap-screen.md) measured only `11.416397058476516341 NVDAB` of new Core deposit headroom, with 26 indexed NVDAB supplier records in an earlier API snapshot. Those records aren't a user count or demand measure. The limited headroom weakens a broad onboarding claim but doesn't invalidate the one-token illustration.

The stronger objections are product-level: zero consenting holder tasks, a sale estimate before final costs, no account-specific post-action borrowing risk, and only a [source-level workflow gap](2026-10-03-same-cash-incumbents.md) against Steward, Venus and Binance Agentic Wallet. The strongest case for keeping the candidate is its concrete same-cash join and observed technical API path. The reviewer judges that insufficient to support the user decision specified in the [one-page spec](../../product/one-page-spec.md).

## Proposed fallback and its own gate

The reviewer prefers the previously investigated [exit or redemption recovery](../../research/2026-10-01-product-brainstorm.md) task over reopening generic purchase readiness or collateral monitoring. That fallback would need a consenting eligible holder with a real blocked or uncertain exit, a balance-bounded signed Binance sell result or exact refusal, and a clearer next action than the issuer, wallet or swap interface. A nonholder quote or competitor README claim wouldn't pass. The reviewer proposes **6 October 12:00 UTC** as its latest go/no-go point to leave five days for a judge path.

## Coordinator decision and dissent

The coordinator does **not** select the fallback yet. It has the same missing holder evidence, so renaming the product wouldn't solve the present blocker. D-017 remains provisional until **4 October 12:00 UTC**, with no further product feature work scheduled ahead of that point. The reviewer treats account-wide risk as already unsafe within the deadline; the coordinator treats that deadline judgment as an inference, since a bounded technical proof might still be possible, but agrees that no personal forecast is currently fit for display.

At the checkpoint, keep D-017 only if a consenting eligible holder's same 100 USDT task shows a concrete decision gain over existing tools, a holder-sized Binance quote supports defensible cost treatment, and personal Venus post-action risk can be represented without implying safety from an isolated market illustration. If any condition fails, retire its cash-choice claim. The exit-recovery fallback requires its own observed task and signed API result before it can be selected. Record a technically interesting prototype as such if neither product passes; don't claim validated demand or a safe financial choice.

**Unknowns:** holder availability, eligibility, final execution costs, deployed Venus arithmetic parity, direct competitor runtime with a holder, and whether the fallback occurs often enough to matter. The Plus CLI did not expose the signed-in email or remaining quota.
