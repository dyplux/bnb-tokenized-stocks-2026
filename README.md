# BNB tokenized stocks project

Working repository for a new Dyplux entry to [BNB Hack: Tokenized Stocks Edition](https://www.bnbchain.org/en/hackathons/tokenized-stocks). The provisional product test compares an NVDAB sale with a Venus USDT borrowing scenario for the same cash target.

## Run the read-only Venus scenario

Requires Python 3.9 or newer and no installed packages. From the repository root, run:

```sh
python3 app/server.py
```

Open `http://127.0.0.1:8000`. Enter NVDAB units and a USDT target, then select **Fetch scenario**. Each request retrieves an indexed snapshot from the public Venus API. The JSON endpoint is `GET /api/scenario?units=1&cash=100`. The request uses `accept-version: next` because the current `stable` response carries a migration warning; the [dated version check](docs/research/2026-10-02-venus-api-version-check.md) records the observed response shapes.

The result appears directly below the amounts. The sell path stays **Unquoted**; the borrow path is a hypothetical market illustration. For the separate sale-route check, enter a public address in the visible **Sale check** panel and select **Request one Binance quote**. Balance and Venus Core reads are under **Optional balance and Venus Core reads**.

An optional public wallet address reads the NVDAB ERC-20 balance through the [official BNB Chain mainnet RPC](https://docs.bnbchain.org/bnb-smart-chain/developers/json_rpc/json-rpc-endpoint/). The server checks chain ID 56, reads contract code and `decimals()` metadata, then calls `balanceOf` at one recorded block. It reports that balance and whether it covers the entered sale units. RPC failure leaves the balance unknown. The address is sent in a POST body, not a URL. The public RPC receives the address in the balance request; this app does not write it to application logs or storage. A public address does not prove ownership or jurisdiction eligibility. This read does not inspect Venus positions.

The separate **Read Venus Core account state** action sends the same optional public wallet in a local JSON POST body to `POST /api/venus-account`. It verifies chain ID 56 and Core Unitroller code, then reads `getAssetsIn(address)` and the direct `userPoolId(address)` getter at one recorded block through Core Unitroller `0xfD36E2c2a6789Db23113685031d7F16329158384`. The entered-market array is strictly bounded and the returned pool ID is validated as `uint96`. The display shows Core market count, selected pool ID, block and timestamp. It does not read supply/debt balances, calculate personal borrow feasibility or liquidation risk, or prove that a new borrow is available. A nonempty market list or nonzero pool ID flags existing Core configuration. An empty list and pool 0 do not establish no debt elsewhere or safe borrowing. RPC or ABI failures leave the account state unknown. The address is not returned, logged or stored.

The optional **Request one Binance quote** action requires `BINANCE_WEB3_API_KEY` and `BINANCE_WEB3_SECRET_KEY` in the process environment or in the ignored repository-root `.env`. Each explicit click first makes one signed, read-only RWA search for `NVDA` on `bstock`. The server requires exactly one result with ticker NVDA, platform BStock, chain 56, the pinned NVDAB contract, symbol NVDAB and stock `assetType=1`; missing, ambiguous or malformed identity data blocks the quote call. Only after that check, it verifies NVDAB's decimals at a recorded BNB block and makes at most one signed `GET /api/v1/dex/aggregator/quote` for the entered NVDAB amount and public wallet. The wallet is sent to Binance in the quote query, but is not put in this app's URL, response or logs. Missing credentials, identity failures, RPC errors, no route and documented API errors are shown as distinct states. A route observation is not verified USDT proceeds: route amount units, fee scope and execution aren't established here. No quote is stored, and the app never requests approval, swap construction, order submission or transaction broadcast. Signing follows the [official authentication guide](https://web3.binance.com/en/dev-docs/authentication), [RWA search reference](https://web3.binance.com/en/dev-docs/llms-full.txt) and [Trading API guide](https://web3.binance.com/en/dev-docs/llms-full.txt); this project has not confirmed the flow with a live signed response.

The Venus panel remains a market-level illustration only, with no wallet debt or collateral, verified sale proceeds, order, transaction, or execution. The sale card stays **Unquoted** and reports no proceeds, even if a quote route is observed. Borrow capacity, hypothetical health factor, liquidation-price stress, pool cash and flat-rate interest figures use isolated assumptions and do not establish personal safety or guarantee borrowing. The panel also checks the entered NVDAB units against indexed Venus supply-cap headroom. A failed cap check means the illustrated deposit may be unavailable; a passed check does not establish that a supply or borrow transaction can execute. [Venus says its indexed API can lag chain state](https://github.com/VenusProtocol/venus-protocol-documentation/blob/main/services/api.md); inspect the displayed source and retrieval time.

## Prepare Binance Web3 credentials

On the SSD, paste a fresh full key pair only into the ignored repository file `/Volumes/SSD500/Dyplux/bnb-tokenized-stocks-2026/.env`, replacing the empty values for `BINANCE_WEB3_API_KEY` and `BINANCE_WEB3_SECRET_KEY`. Do not put either secret in chat, commits, logs or demos. Start the server from the repository root with `python3 app/server.py`, then open `http://127.0.0.1:8000`. The **Request one Binance quote** action performs one signed, read-only RWA identity search and, only when that identity is unambiguous, at most one signed quote request for the entered NVDAB amount and public wallet; it does not submit, approve or broadcast a transaction. Keep the pair in `.env` only; use `.env.example` as the empty-field template.
